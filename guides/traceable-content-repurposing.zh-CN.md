# 把文章改成渠道稿：先做主张卡，再写草稿

[English](traceable-content-repurposing.md) · 作者 [BBQ](https://bbqgrowthlab.com/zh-cn/about/) · 资源版本 v0.3.0

适合已有专业文章、研究笔记或案例底稿，需要改成微信、LinkedIn 或邮件内容的顾问与编辑。输入正文、读者、一个目标渠道和希望读者采取的行动，得到主张卡、渠道制作卡、草稿与来源映射。只有标题时，先补素材。

方法来自 BBQ 的[内容复用与多渠道分发文章](https://bbqgrowthlab.com/zh-cn/articles/content-repurposing-map-seo-llm-visibility/)，具体提炼了“主张卡”“渠道制作卡”和“版本影响清单”。原文解释完整方法，这份资源帮助你把自己的材料带入执行。

## 四步完成一次可追溯改写

1. **整理来源。** 给原文或笔记一个记录名、日期或版本；标明来源段落、事实归属、假设示例和未知项。
2. **提取主张。** 为关键表达建立 C1、C2 等 ID，记录“说了什么、来自哪里、能支持到什么程度”。来源写过不代表已经独立核实。
3. **制作渠道卡。** 选一个读者任务、需要的主张和一个行动，明确不能删除的限制。未知负责人、复查日期或平台上限保持未指定。
4. **写稿并对照。** 交付一份渠道稿；用独立编辑表连接草稿表达与主张 ID。事实归属、演示标签和必要限制保留在正文里。

## 可以直接使用的输入

```text
使用 bbq-content-repurposing，为下面材料制作一份可追溯内容包：
主张卡、一个渠道制作卡、中文微信短文、单独的来源映射。
读者：独立顾问。行动：挑一篇自己的旧文，标出观点、来源和限制。
来源 S1，版本 2026-09-22：
第1段：复用专业文章时，先选能回答目标读者问题的一条观点，
保留原始证据、出处与适用条件，再按渠道场景重写。
第2段：建议在草稿之外记录关键表达来自哪一段，事实修订后据此定位待检查版本。
这是建议流程，尚未测量节省时间、流量或咨询变化。
不要联网或发布；只生成微信一个版本。
```

完整测试输入见 [normal.input.md](../validation/content-repurposing/v0.3.0/normal.input.md)，实际 Codex 输出见 [normal.codex.output.md](../validation/content-repurposing/v0.3.0/normal.codex.output.md)。测试材料是为验证行为编写的方法示例，不是客户结果。

预期的编辑记录形态如下，具体措辞不必相同：

| 主张 | 来源 | 草稿应保留什么 |
| --- | --- | --- |
| 先选一个读者问题再改写 | S1 第1段 | 方法建议，而非已验证增长结果 |
| 保留证据、出处和适用条件 | S1 第1段 | 不能把他人研究变成本人业绩 |
| 记录表达与原文段落的关系 | S1 第2段 | 修订后可以定位待检查内容，不代表已经自动更新 |
| 尚未测量业务变化 | S1 第2段 | 草稿中明确保留测量限制 |

## 验收和限制

检查正文而不只看模型自报的核查表：原文是否真的支持每条关键表达？数字是否采用明确的最新来源？演示是否仍写为演示？是否保留未测量的限制？请求一个渠道时有没有擅自增加其他稿件？
